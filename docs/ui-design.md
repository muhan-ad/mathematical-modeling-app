# 数模解题 Agent 桌面应用 — UI 设计规范

> 版本：v0.1
> 日期：2026-09-05
> 配套文档：[design.md](design.md)（产品方案）/ 当前已实现基座（Electron + React + Tailwind + shadcn/ui）

## 1. 设计理念

### 1.1 设计哲学

**"思考型工具"（Thoughtful Tool）**——专为深度工作设计，不是消费级应用。

数模比赛是高强度脑力活动，用户在 72 小时内持续处于"建模—验证—写作"的循环。UI 的核心任务不是"好看"，而是**降低认知负荷、放大用户判断力**：

| 原则 | 含义 | 设计映射 |
|------|------|----------|
| **聚焦** | 任何时候屏幕上只有一个主任务 | 三栏布局，中间是对话流，左右是辅助信息，可折叠 |
| **透明** | Agent 在做什么、为什么这么做，永远可见 | 流式 token 渲染 + 工具调用展开卡片 + 阶段进度条 |
| **可控** | 用户随时能介入、纠偏、回滚 | 审批门 + 手动接管 + Diff 视图 + 状态快照回滚 |
| **耐看** | 长时间使用不疲劳 | 暗色主题为主，低饱和度配色，无强对比闪烁 |
| **可读** | 公式、代码、论文是核心内容 | 等宽字体 + LaTeX 渲染 + 代码语法高亮 |

### 1.2 与通用 LLM 对话界面的区别

通用对话（ChatGPT/Claude）是"一问一答流"，本应用是"项目工作台"：

- **左侧文件树**：项目目录可见，让用户有"在工作"的实感
- **中间对话流**：与 Agent 交互，但每个消息可附带"工具调用卡片"和"产物预览"
- **右侧预览**：当前产物的实时预览（代码运行结果、图表、PDF 页）
- **顶部阶段条**：5 阶段进度，全局状态一目了然

## 2. 色彩搭配方案

### 2.1 主题策略

**默认暗色主题**（已在 [styles.css](../src/renderer/src/styles.css) 实现），原因：
- 长时间使用护眼
- 代码、公式、图表在暗背景下更清晰
- 与 VS Code / Cursor 等开发工具视觉一致，目标用户（理工科学生）熟悉

可选浅色主题（Phase 4），但不是 MVP 重点。

### 2.3 视觉对比度

所有文字与背景对比度 ≥ 4.5:1（WCAG AA 标准），主文字 ≥ 7:1（AAA）。

## 3. 排版系统

### 3.1 字体栈

```css
--font-sans: 'Segoe UI', system-ui, -apple-system, sans-serif;    /* UI 文字 */
--font-mono: 'Cascadia Code', 'Consolas', monospace;              /* 代码/公式 */
--font-serif: 'Latin Modern Roman', 'Times New Roman', serif;     /* 论文预览 */
```

- **Segoe UI**：Windows 系统原生，渲染清晰，与系统视觉一致
- **Cascadia Code**：微软现代等宽字体，连字（ligatures）让代码更易读
- **Latin Modern Roman**：LaTeX 默认字体的 Web 版，论文预览时用

### 3.2 字号阶梯（Type Scale）

基于 1rem = 16px，比例 1.25（Major Third）：

| Token | px | 用途 |
|-------|-----|------|
| `text-xs` | 12 | 辅助标签、版本号、时间戳 |
| `text-sm` | 14 | 次要正文、表格、表单 |
| `text-base` | 16 | 默认正文（对话流） |
| `text-lg` | 18 | 副标题 |
| `text-xl` | 20 | 卡片标题 |
| `text-2xl` | 24 | 页面区块标题 |
| `text-3xl` | 30 | Hero 标题（首页） |
| `text-4xl` | 36 | 大标题（仅首页） |

### 3.3 行高与间距

| 场景 | 行高 |
|------|------|
| 正文（段落） | 1.7（loose） |
| UI 文字 | 1.5（normal） |
| 标题 | 1.2（tight） |
| 代码块 | 1.5 |

字间距：标题 `-0.02em`（紧凑显稳重），正文 `0`，等宽 `0`。

### 3.4 排版规则

- 中文与英文/数字之间自动加 0.25em 间距（CSS `text-spacing-trim` 或手动 ` ` ）
- 长段落最大宽度 `max-w-prose`（65ch），避免行长过宽难追读
- 代码块默认带行号、复制按钮、语言标签

## 4. 交互模式

### 4.1 对话流交互

用户与 Agent 的主要交互方式。每条消息分**用户气泡**和**Agent 回复**两种：

```
┌─ User ─────────────────────────────────────────┐
│ 帮我把第二问的优化模型改成 MILP                    │
└────────────────────────────────────────────────-┘
                                              16:32

┌─ Agent (建模阶段) ────────────────────────────┐
│ 好的，我把第二问的 LP 改成 MILP。改动如下：       │
│                                                  │
│ ┌─ 工具调用: edit_file ─────────────────────┐  │
│ │ 📝 workspace/code/solve_q2.py              │  │
│ │ + from pulp import LpProblem, LpVariable  │  │
│ │ + prob = LpProblem("q2", LpInteger)        │  │
│ │ [展开 diff ↓]                              │  │
│ └────────────────────────────────────────────┘  │
│                                                  │
│ 已修改，要我重新跑一遍验证吗？                     │
│                                                  │
│ [▶ 立即运行]  [稍后]                              │
└────────────────────────────────────────────────┘
                                              16:33
```

**流式渲染**：Agent 回复按 token 流式显示，光标闪烁表示生成中。工具调用卡片在 Agent 发起调用时**立即出现**（不等返回），让用户感知"Agent 在做事"。

### 4.2 审批门交互

每个阶段产出后，对话流末尾出现**审批门卡片**：

```
┌─ ⏸ 阶段审批：建模 ─────────────────────────────┐
│ Agent 已完成建模，产出物：                         │
│   • 模型假设（5 条）                              │
│   • 变量定义（12 个）                             │
│   • 数学公式（3 个）                              │
│   • 求解策略：scipy.optimize.milp                │
│                                                  │
│ [📋 查看完整方案]                                 │
│                                                  │
│ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │
│ │  ✓ 通过     │ │  ↩ 打回     │ │  ✎ 手动改  │ │
│ │ 进入求解    │ │ 让Agent重做 │ │ 我自己编辑 │ │
│ └─────────────┘ └─────────────┘ └─────────────┘ │
└──────────────────────────────────────────────────┘
```

- **通过**：进入下一阶段，进度条推进
- **打回**：Agent 带反馈重做当前阶段（输入框填反馈）
- **手动改**：打开方案编辑器，用户改完 Agent 继续

### 4.3 手动接管

用户可随时直接操作项目目录：
- **编辑代码**：在文件树点开 `.py`，内置 Monaco Editor 编辑
- **编辑 LaTeX**：点开 `.tex` 同样可编辑
- **手动跑代码**：代码块右上角"运行"按钮
- Agent 下次执行时读取最新版文件，不会覆盖用户改动

### 4.4 键盘快捷键

| 快捷键 | 作用 |
|--------|------|
| `Ctrl+K` | 全局命令面板（搜文件/Agent 操作） |
| `Ctrl+Enter` | 发送对话消息 |
| `Shift+Enter` | 换行（对话输入框） |
| `Ctrl+B` | 折叠/展开左栏 |
| `Ctrl+J` | 折叠/展开右栏 |
| `Ctrl+P` | 预览当前产物（PDF/图） |
| `Ctrl+Z` | 撤销（编辑器内） |
| `Ctrl+Shift+Z` | 回滚到上一个阶段快照 |
| `Esc` | 关闭弹窗/退出全屏预览 |

### 4.5 拖拽与文件操作

- **拖拽上传**：题目 PDF / 数据 Excel 直接拖到窗口任意位置，自动归到 `problem/attachments/`
- **文件树右键**：重命名、删除、在外部资源管理器打开
- **代码块拖拽**：可拖到对话输入框引用（生成 `[引用: solve_q2.py]` 标签）

### 5.3 业务复合组件设计

#### 5.3.1 `StageProgress`（阶段进度条）

顶部横向 5 节点，显示当前阶段、各阶段状态。

```
[1 理解]──[2 建模]──[3 求解]──[4 写作]──[5 校对]
   ✓        ⏸ 待审批   ○        ○        ○
```

| 节点状态 | 视觉 |
|----------|------|
| 完成 | 实心圆 + 绿色 + ✓ |
| 进行中 | 实心圆 + 蓝色 + 脉冲动画 |
| 待审批 | 实心圆 + 橙色 + ⏸ |
| 未开始 | 空心圆 + 灰色 |
| 失败 | 实心圆 + 红色 + ✗ |

点击节点：跳到该阶段对话起点（已完成的可跳，未到的禁用）。

#### 5.3.2 `ApprovalGate`（审批门卡片）

见 § 4.2 设计图。变体：
- `default`：三按钮（通过/打回/手动改）
- `auto`：自动通过模式，仅显示"继续"按钮
- `failed`：失败重试，显示错误摘要 + "重试"/"修改方案"

#### 5.3.3 `MessageBubble`（消息气泡）

| 类型 | 对齐 | 头像 | 样式 |
|------|------|------|------|
| User | 右 | 无 | `bg-primary/10` 圆角 |
| Agent | 左 | Agent 头像（首字母） | `bg-card` 边框 |
| System | 中 | 无 | `bg-muted` 小字斜体 |

Agent 消息支持嵌套：
- 文本段（支持 Markdown 渲染，含 LaTeX 公式 `$...$` / `$$...$$`）
- 工具调用卡片（`ToolCallCard`）
- 产物预览（图/PDF 缩略图）
- 操作建议按钮组

#### 5.3.4 `ToolCallCard`（工具调用卡片）

```
┌─ 🔧 execute_python ─────────── 0.8s ─┐
│ 输入: solve_q2.py                      │
│ ┌─ 折叠: stdout (12 行) ───────────┐ │
│ │ Optimization terminated successfully│ │
│ │ Objective: 12.4                   │ │
│ └──────────────────────────────────┘ │
│ 产出: workspace/figures/q2_result.png │
│                                       │
│ [▶ 在编辑器打开] [👁 预览图]            │
└───────────────────────────────────────┘
```

- 标题行：工具名 + 耗时
- 内容：可折叠的输入/输出
- 产出物：列出文件路径 + 快速预览/打开按钮
- 失败时：红色边框 + 错误堆栈展开

#### 5.3.5 `FileTree`（文件树）

基于 `react-arborist` 或自实现。特性：
- 项目目录结构展示
- 文件类型图标（`.py` / `.tex` / `.pdf` / `.png` 各一色）
- 点击在编辑器/预览器打开
- 右键菜单（重命名/删除/外部打开）
- 实时监听文件系统变化（chokidar 推送）

#### 5.3.6 `CodeEditor`（代码编辑器）

集成 **Monaco Editor**（VS Code 同款）：
- Python / LaTeX 语法高亮
- 行号、缩进辅助
- 基础 LSP（可选，Phase 4）
- 保存按钮 + `Ctrl+S`

#### 5.3.7 `PdfPreview`（PDF 预览）

集成 **pdfjs-dist**：
- 内嵌预览面板
- 页码导航 / 缩放
- 侧边缩略图栏
- 全屏切换
- 编译失败时显示 `.log` 错误高亮

### 5.4 组件 API 规范

所有业务组件遵循：
- TypeScript 严格类型，props 接口导出
- 受控 + 非受控兼容（仿 shadcn 模式）
- 不在组件内发请求，数据通过 props 注入
- 事件回调用 `onXxx` 命名

## 6. 响应式布局策略

### 6.1 应用类型与窗口尺寸

桌面应用，非移动端。但用户可能调整窗口大小，需自适应：

| 尺寸 | 范围 | 策略 |
|------|------|------|
| 最小 | 900×600 | 低于此值禁用部分功能（如折叠双栏） |
| 默认 | 1200×800 | 已在 [main/index.ts](../src/main/index.ts) 配置 |
| 舒适 | 1440×900+ | 三栏全展开 |
| 全屏 | 任意 | 中栏最大化，左右栏可悬浮 |

### 6.2 断点策略

由于桌面应用，不用 Tailwind 默认的移动优先断点。自定义：

| 断点 | 触发条件 | 行为 |
|------|----------|------|
| `compact` | width < 1100 | 左栏自动折叠为图标条 |
| `cozy` | 1100 ≤ width < 1440 | 左栏 240px，右栏折叠为标签条 |
| `comfortable` | width ≥ 1440 | 三栏全展开：240 / flex / 360 |
| `fullscreen` | width ≥ 1920 | 右栏 480，中栏居中限宽 |

### 6.3 三栏布局实现

```tsx
<div className="flex h-screen">
  <aside className="w-60 border-r shrink-0"> {/* 左栏：文件树 */}
    <FileTree />
  </aside>

  <main className="flex-1 flex flex-col min-w-0"> {/* 中栏：对话 */}
    <header className="h-14 border-b shrink-0">
      <StageProgress />
    </header>
    <div className="flex-1 overflow-y-auto">
      <ChatStream />
    </div>
    <footer className="border-t shrink-0">
      <ChatInput />
    </footer>
  </main>

  <aside className="w-96 border-l shrink-0"> {/* 右栏：预览 */}
    <PreviewPanel />
  </aside>
</div>
```

`min-w-0` 防止中栏被压缩时溢出。`shrink-0` 让边栏不被压缩。

### 6.4 可折叠侧栏

用户可一键折叠左/右栏（`Ctrl+B` / `Ctrl+J`）：
- 折叠后只剩窄条 + 展开按钮
- 鼠标悬停窄条可临时悬浮展开（不挤压中栏）
- 状态持久化（下次打开窗口恢复）

## 7. 用户体验优化措施

### 7.1 加载与等待状态

| 场景 | 处理 |
|------|------|
| Agent 思考中（首 token 前） | 对话区显示骨架屏 + "Agent 思考中..." 文字 + 脉冲点 |
| Agent 流式输出 | token 逐字渲染，光标闪烁 |
| 工具执行中 | ToolCallCard 显示 spinner + "执行中..." |
| LaTeX 编译中 | 进度条 + 当前步骤（pdflatex 第几遍） |
| 长任务（>3s） | 显示已耗时 + "取消" 按钮 |

### 7.2 错误处理

| 错误类型 | UI 反馈 |
|----------|---------|
| API 调用失败 | Toast 红色 + 重试按钮 + "检查设置"链接 |
| 代码执行报错 | ToolCallCard 红色边框 + stderr 折叠展开 |
| LaTeX 编译失败 | 右栏切换到 "Log" 标签 + 错误行高亮 + "让 Agent 修复"按钮 |
| 文件不存在 | 文件树灰显 + 提示"已被删除" |
| 网络断开 | 顶栏红条 + "已离线，仅本地工具可用" |

### 7.3 空状态

每个区域有友好的空状态：

| 区域 | 空状态文案 |
|------|-----------|
| 项目列表 | "还没有项目，创建第一个开始你的数模之旅" + 大按钮 |
| 文件树 | "项目刚创建，Agent 还没产出文件" |
| 对话流 | "向 Agent 提问，或上传题目开始" + 示例 prompt 按钮 |
| 预览面板 | "选择一个文件预览" |
| 设置页 | "还没配置模型，先填 API key 才能开始" |

### 7.4 流式输出优化

- **虚拟滚动**：长对话用 `react-virtuoso` 渲染，避免 DOM 节点爆炸
- **节流渲染**：token 每 50ms 批量 flush 一次，不每个 token 都触发 React rerender
- **自动滚动**：用户在底部时自动跟随，向上滚动时暂停跟随（避免抢用户阅读）

### 7.5 撤销与回滚

- **编辑器撤销**：标准 Ctrl+Z
- **阶段回滚**：每个阶段有"快照"，用户可"回到此阶段重做"，状态快照存 `state.json`
- **文件历史**：项目目录内置 `.history/`（git 仓库自动版本化），右键文件"查看历史"

### 7.6 可访问性

- 所有交互元素键盘可达（Tab 顺序合理）
- 焦点环可见（`focus-visible:ring-2`）
- 颜色对比度达 WCAG AA
- 屏幕阅读器友好（语义化 HTML + ARIA 标签）
- 尊重 `prefers-reduced-motion`（关闭动画）

## 12. 实现细节

### 12.1 主题变量注入位置

所有 CSS 变量定义在 [src/renderer/src/styles.css](../src/renderer/src/styles.css) 的 `:root`，配合 `tailwind.config.ts` 映射成 Tailwind 工具类：

```tsx
// 使用示例
<div className="bg-card text-foreground border border-border rounded-lg">
  <h2 className="text-xl font-semibold text-primary">标题</h2>
  <p className="text-sm text-muted-foreground">说明</p>
</div>
```

### 12.2 暗色主题切换（Phase 4）

```tsx
// 通过 class 切换
<html className="dark">  <!-- 暗色（默认） -->
<html className="">      <!-- 浅色 -->

// styles.css
.dark { --background: 222 22% 8%; ... }
:root { --background: 0 0% 100%; ... }
```

### 12.3 图标系统

统一用 `lucide-react`，已配置。规范：
- 默认尺寸 `size-4`（16px），紧凑场景 `size-3.5`
- 按钮内图标与文字间距 `gap-2`
- 不混用 emoji 和 SVG 图标

### 12.4 动画规范

| 场景 | 动画 | 时长 |
|------|------|------|
| 按钮 hover | 背景色变化 | 150ms |
| 弹窗出现 | 淡入 + 轻微缩放 | 200ms |
| Toast | 右滑入 + 淡入 | 250ms |
| 阶段进度推进 | 节点填充 + 连线延展 | 400ms |
| 流式光标 | 闪烁 | 1s loop |
| 加载骨架 | 脉冲 | 1.5s loop |

用 `tailwindcss-animate` 提供的 `animate-in` / `animate-out` 工具类。

### 12.5 国际化（i18n）

MVP 仅中文。但所有文案走 `t('key')` 函数（`i18next`），为后续英文支持预留：

```tsx
import { useTranslation } from 'react-i18next'
const { t } = useTranslation()
return <Button>{t('project.create')}</Button>
```

### 12.6 字体加载

- Segoe UI / Cascadia Code：系统自带，无需加载
- Latin Modern Roman：打包到应用，仅 PDF 预览组件用
- 不引入 Google Fonts，避免首屏卡顿
